# GreenShield Design Direction

Primary archetype: Data-heavy technical product with restrained SaaS landing.

Reason:
GreenShield sells trust for AI applications. The UI should feel like a precise security console, not a generic cyber landing page. Marketing pages may explain the product, but visible UI should keep evidence, risk, findings, and retest workflow close to the surface.

Rules:
- Use matte dark surfaces, thin borders, and restrained emerald accent.
- Avoid heavy glassmorphism, neon glow, decorative blobs, and repeated equal cards.
- Use cards only for product data, findings, plans, or concrete summaries.
- Use cyan for progress or focus, amber for warning, rose for high/critical, emerald for brand/pass/action.
- Prefer table, split-pane, timeline, and report patterns for product UI.
- Keep homepage sections visually distinct: hero console, risk scenarios, workflow rail, risk matrix, pricing preview.

## 2026-06-30 landing reset

The public homepage should not present a fake dashboard beside the hero headline. It should first explain the product value, then use a meaningful AI attack-surface visual to show what GreenShield protects.

Updated rules:
- Hero uses one value proposition, one short paragraph, one primary CTA, and one secondary CTA.
- Hero visual should be conceptual or animated, not a fake webpage screenshot.
- Metrics must be credible and useful. Do not add numbers only to fill space.
- Pricing must include plan cards plus a capability comparison matrix.
- Problem, workflow, report, and pricing sections should use different layout families.
- Public marketing pages are Vietnamese-first because the primary customer is in Vietnam. Keep technical terms such as LLM, RAG, API, prompt injection, and retest when they are clearer than forced translation.
- Public navigation should look like a real website: product sections, report, pricing, contact, and a single strong CTA. Dashboard and internal scan routes should not dominate the marketing nav.

## 2026-06-30 reference audit update

Reviewed ATIN, Pangea, and VNETWORK as public-facing AI/security/cloud references.

Applied lessons:
- Make the first viewport readable immediately. Do not let dark overlays, delayed reveal, or low contrast hide the value proposition.
- Use one sharp product promise plus one primary trial CTA, then show proof/trust immediately below.
- Visuals must carry product meaning: attack surface, score, findings, and retest state are more useful than decorative cyber panels.
- Vietnamese-first copy should stay direct and business-oriented for local startup/SME buyers.
- Keep public homepage sections distinct: hero/proof, platform fit, risk explanation, workflow, report preview, pricing, CTA.
